# REF/VAULT

Локальная библиотека визуальных референсов для дизайнеров. Вставь ссылку на работу или загрузи файл, выбери медиа и обложку, добавь теги, коллекцию и заметку. REF/VAULT скачивает изображения и видео на твой компьютер, чтобы можно было вернуться к ним независимо от доступности исходной страницы.

Проект работает на Node.js, Express и Playwright; интерфейс написан на обычных HTML, CSS и JavaScript без сборки. Текущая версия — **0.3.0**.

## Возможности

- Импорт публичных работ из Dribbble, Behance, Pinterest, Are.na и Instagram.
- Галереи Pinterest и карусели Instagram; выбор отдельных файлов и обложки перед сохранением.
- Ручная загрузка изображений и видео.
- Сетка с исходными пропорциями превью и воспроизведением видео при наведении.
- Поиск, фильтры по тегам и коллекциям, просмотр сохранённого набора медиа.
- Редактирование заметок, тегов и коллекций; массовое добавление тегов, перенос в коллекцию и удаление.
- Импорт медиа из выгрузки Raindrop и необязательная очередь JSON для ссылок с телефона.

## Быстрый старт и свой форк

Нужны **Node.js 24 или новее**, npm и Git. Основное приложение не требует аккаунтов или API-ключей. Для распознавания ссылок и первого скачивания файлов нужен интернет; библиотека хранится локально.

1. Нажми **Fork** в GitHub, чтобы создать свою копию проекта.
2. Скопируй адрес своего форка из кнопки **Code** и выполни:

```bash
git clone https://github.com/YOUR_USERNAME/ref-vault.git
cd ref-vault
npm ci
npm run browser:install
npm run dev
```

Открой **http://localhost:3000**. При первом запуске приложение автоматически создаст пустую библиотеку в `data/`. Для обычного запуска достаточно `npm run dev`; `Ctrl+C` останавливает сервер.

На Linux Playwright может попросить системные библиотеки для Chromium: установи их командой `npx playwright install --with-deps chromium`. Импорт Raindrop дополнительно требует Python 3.10+; генератор постеров на Swift предназначен для macOS.

Чтобы изменить порт или папку хранения, скопируй `.env.example` в `.env`, раскомментируй нужную строку и перезапусти сервер. Для нового пути используй абсолютный путь. Пустые необязательные переменные задавать не нужно.

Приложение предназначено для локального использования. У сервера нет авторизации: не публикуй его порт в интернете. Папки с личной библиотекой, экспортами, очередью, макетами и локальные `.env` исключены из Git.

## Разработка

```bash
npm test
```

Тесты проверяют адаптеры Instagram/Pinterest, очередь Inbox и массовые операции. Для записей используется временная библиотека; личные рефы не затрагиваются.

Основные файлы: `server.js` — API и сохранение; `public/` — интерфейс; `pinterest.js` и `instagram.js` — адаптеры; `inbox.js` — очередь; `scripts/` — импорт Raindrop; `tests/` — тесты. Сборка перед запуском не требуется.

## Как устроена библиотека

- Карточка показывает **выбранное медиа** как cover; по умолчанию выбрано первое.
- При сохранении архивируется **выбранный набор** изображений и видео из работы.
- Один референс содержит массив `media[]`.
- Нажатие на cover открывает весь сохранённый набор.
- Хранилище можно вынести из проекта, например в локальную синхронизируемую папку Яндекс Диска.

## Хранение в Яндекс Диске
Найди локальную папку Яндекс Диска на Mac и создай внутри неё, например, `REF-VAULT`.

В `.env` проекта добавь:
```env
REF_VAULT_STORAGE_DIR="/полный/путь/до/Яндекс Диска/REF-VAULT"
```

После перезапуска в Terminal появится:
```text
Storage → /полный/путь/...
```

Туда будут записываться и `db.json`, и папка `media/`, поэтому библиотека будет синхронизироваться облаком.

Важно: путь у разных установок Яндекс Диска отличается. Не угадывай его — открой папку Яндекс Диска в Finder, набери в Terminal `cd ` и перетащи папку в окно: Terminal подставит точный путь.

## Импорт конкретной работы

Dribbble: медиа собираются из блоков самой работы, после прокрутки для загрузки lazy images. Behance, Are.na и Pinterest используют отдельные селекторы основного контента. Если блок не распознан, импорт ограничивается метаданными страницы и показывает предупреждение; рекомендации со всей страницы не собираются.

Instagram: поддерживаются публичные ссылки `/p/…`, `/reel/…` и `/tv/…`. Из данных конкретного поста собираются карусели, выбираются самые крупные доступные изображения и видео; обложки видео сохраняются как poster. Параметры шеринга удаляются из ссылки. Если обычная страница не отдаёт медиа, проверяется публичная embed-версия. Закрытые посты, Stories и страницы профилей не поддерживаются; для доступного только превью показывается предупреждение о неполном наборе.

Перед сохранением можно снять галочки с ненужных медиа. Обложка выбирается из сохранённых изображений; для видео отдельно сохраняется локальный poster, если он доступен. Галереи Pinterest читаются из данных конкретного пина, включая ID исходной публикации для репинов: изображения сохраняют порядок галереи, а размерные варианты дедуплицируются. Для каждой картинки запрашивается оригинал; если он недоступен, используется доступный вариант большего размера. Для видеопинов прямой MP4 берётся из структурированных метаданных конкретного пина; временные blob-адреса плеера не скачиваются. Обложка сохраняется как poster видео. Pinterest не прокручивается, чтобы рекомендации не подменяли метаданные публикации. Если не удалось скачать ни одного файла, карточка не создаётся.

Площадки могут менять структуру страниц, требовать вход или ограничивать скачивание. Если доступен только файл из метаданных страницы, приложение показывает предупреждение: проверь набор перед сохранением. Галерея Pinterest проверена на публичном пине с тремя изображениями; отдельные работы могут обрабатываться иначе.

Для прямых ссылок Are.na `/block/ID` импорт сначала запрашивает публичный API блока и берёт оригинальное изображение/GIF или видео-вложение с постером. Если API недоступен, используется чтение страницы. Проверен полный импорт блока 50913640: оригинальный GIF, 5 802 290 байт.

## С телефона через iCloud Inbox

iPhone → JSON в **iCloud Drive / REF-VAULT Inbox** → очередь на Mac → текущая локальная библиотека. Сервер должен быть запущен; отправленные при выключенном Mac задания дождутся синхронизации и запуска REF/VAULT. Автозапуск сервера пока не настраивается.

Блок «С телефона» пока скрыт в интерфейсе; серверный watcher сохранён. Пошаговая инструкция доступна по адресу **http://localhost:3000/shortcut-setup.html** и лежит в `public/shortcut-setup.html`. Есть быстрый сценарий (только ссылка) и вариант с тегами, заметкой и коллекцией. Поля необязательные; коллекция по умолчанию — `Inbox / Без разбора`.

Стандартная папка на Mac: `~/Library/Mobile Documents/com~apple~CloudDocs/REF-VAULT Inbox`. Она не создаётся искусственно, если iCloud Drive не подключён. Для другой папки добавь в `.env`:

```env
REF_VAULT_INBOX_DIR="/точный/локальный/путь/REF-VAULT Inbox"
```

Формат задания (один объект в одном `.json`, максимум 1 МБ):

```json
{
  "url": "https://www.are.na/block/50913640",
  "tags": ["motion"],
  "note": "Нравится анимация",
  "collection": "",
  "createdAt": "2026-10-03T12:00:00+03:00"
}
```

Теги также принимаются строкой через запятую. Watcher опрашивает папку каждые 3 секунды и ждёт стабильного размера/времени изменения файла. Задания обрабатываются последовательно. Состояния: `queued`, `processing`, `saved`, `error`; частично скачанная работа помечается отдельно. Статусы и задания хранятся в `data/inbox-queue.json` (или в настроенном хранилище). После перезапуска незавершённое задание возобновляется; `inboxJobId` в карточке защищает от повторного создания карточки после сбоя между сохранением работы и статуса очереди.

Исходные JSON остаются в Inbox, не удаляются и не перемещаются. Имя + содержимое определяют идентификатор: повторное сканирование не создаёт новую карточку, новая отправка в новом файле считается самостоятельным заданием. Исправленный файл создаёт новое задание; старое сообщение об ошибке остаётся в истории. Кнопка «Повторить» повторяет существующее задание после ошибки скачивания. Восстановление после удаления карточки не выполняется автоматически.

`npm test` проверяет обработку очереди на временных папках. Для установки на телефон требуется настроить iCloud Drive и создать команды по инструкции: подпись автоматически собранных `.shortcut` на этом Mac невозможна без входа в iCloud. `shortcuts/build.py` сохраняет исходники для последующей подписи; они ещё не проверены запуском на iPhone.

## Интерфейс и шрифт

Основной экран — строка URL (Enter или вставка запускает проверку), кнопка «+» для ручного добавления и библиотека с поиском, фильтрами по тегу/коллекции и переключателями изображений/видео. Карточки показывают cover, источник и число медиа. Теги, коллекция, заметка, ссылка на оригинал и удаление доступны в просмотрщике. Перед импортом можно исключать отдельные медиа. Подсказки в формах берутся из сохранённой библиотеки.

iCloud Inbox временно скрыт атрибутом `hidden` у `.inboxSection`; очередь и серверный watcher сохранены. Скрытый блок не опрашивает API в браузере.

Иконки хранятся в `public/assets/`. Интерфейс использует системный шрифт. Опционально CSS поддерживает YS Text Web из `public/assets/ys-text-web.ttf`: если у тебя есть право на его использование, можно добавить файл локально. Сам файл шрифта и личные макеты в репозиторий не включены.

## Импорт Raindrop

В `data/raindrop/` сохраняются исходный `export.zip` и дополнительные CSV. Импорт переносит только картинки и видео: оригиналы из ZIP, прямые ссылки на медиа и медиа из поддерживаемых страниц рефов. Обычные закладки остаются вне библиотеки. Одинаковые имена файлов различаются по исходной дате ZIP; теги и коллекции сопоставляются без учёта регистра, «градиенты» объединяются с «градиент», «Интерфейсы» — с «интерфейс». Отсутствующие коллекции не угадываются.

Подготовка скачивает файлы в `data/media/`, но не меняет базу:

```sh
python3 scripts/import-raindrop.py prepare --inspector http://localhost:3000
```

В `data/raindrop/import-<дата>/` появляется `plan.json`, список недоступных оригиналов/ссылок и задания для локальных постеров видео. Для постеров на macOS:

```sh
swiftc scripts/raindrop-video-posters.swift -o /tmp/ref-raindrop-posters
/tmp/ref-raindrop-posters data/raindrop/import-<дата>/poster-jobs.json data/raindrop/import-<дата>/poster-result.json
```

После проверки плана остановить сервер на время записи и выполнить:

```sh
python3 scripts/import-raindrop.py commit --plan data/raindrop/import-<дата>/plan.json
```

Импорт сохраняет исходные даты и сортирует библиотеку от новых к старым. Перед записью создаётся копия базы `db-before-*.json`, после — `report.json`. Повторное применение того же плана ничего не меняет: идентификаторы Raindrop защищают от дублей. Файлы, которых нет в ZIP и которые требуют входа в Raindrop, перечисляются в отчёте для следующей выгрузки.
